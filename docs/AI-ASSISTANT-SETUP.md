# Conversational deck assistant — implementation checkpoint

The Assistant screen opens a conversational AI tab alongside New deck and Upgrade existing deck. Guest and account libraries are supported. Context includes the selected deck or optional commander, a new-purchase budget, saved bracket target, notes and verified collection cards. Up to five nonland one-for-one swaps require explicit review and server revalidation. Chat never saves a deck. New ideas receive advice, not automatic deck creation. Changing context clears the conversation. Nothing is fine-tuned or trained in this implementation.

## Validation and bounds

Server fetches current/cached Scryfall facts by fixed routes; the model cannot choose network URLs. Context is limited to 110 unique supplied printings plus bounded deterministic commander searches. Larger collections receive a visible error. Only active account-owned documents enter account context. Guest proposals cannot apply to account documents. Review records expire after 15 minutes, are consumed once, and are held in memory; restarting invalidates reviews. Content/revision/inventory changes invalidate a review. Code checks color identity, legality, singleton, bracket rules, cost/owned constraints, commander and 100-card preservation. Named cards in deck notes and lands are protected. Rule checks cannot certify every combo or power level. Source quotes may be cached up to 24 hours; taxes/shipping excluded.

Conversation and advice are untrusted text, rendered without HTML. Exact referenced card IDs must be grounded; unknown IDs, invalid structured output, refusal, incomplete output, invalid cuts/additions and unsafe proposals fail without save. Cancel aborts the request locally; an already-started provider request may still be charged. No background polling, training, arbitrary tools, purchases or automatic deck changes.
