# Guest-first library and full Commander builder — October 15

## Use

Run npm run dev:all from the project root; use npm run expo only for the native shell. Existing running stack is LAN192.168.4.25:5173, Metro8081. Create decks, binders and lists directly; no account required. Guest saves/history/moves use a versioned local browser library. Editing, trash/restore, card imports and TXT/CSV/JSON exports, recommendations and playtesting use the selected local or account library. Settings offers full guest export and JSON import (a single document or archive). Imports deliberately create new IDs, including repeated imports; existing documents remain intact.

Guest data is local to this browser/device AND web origin/server address. It is not automatically backed up. Clearing browser/app data can remove it, and a changed LAN/server origin can make it inaccessible until returning to that origin or importing an export. The Expo shell still loads the served web app; fully offline cold launch is not implemented. Local saves/editing/export work without API/network access after the app is loaded; search/card verification/recommendations/build-pool retrieval require the server/provider. Export regularly. Storage errors and corrupt data are surfaced, never reported as successful saves. The preserved raw guest recovery file can be downloaded if readable.

Sign-in is optional for a separate library stored on this server. A local SQLite server is not a cloud backup. Settings switches guest/account libraries without caching account documents into guest storage. Signout returns to guest originals. Copy-to-account is deliberate per guest document/version: the server creates new document and row IDs, never replaces account documents, and atomically records a per-account retry token. A lost response can be retried without a duplicate; receipts remain isolated by account. Guest originals are never removed. Changes to a guest version permit a new explicit copy. No real-user login, logout, password change or account registration was performed in testing.

## Full Commander construction

More → Deck assistant → Build a full Commander deck. Enter an exact commander name or a supported keyword theme (tokens/goblins, counters/proliferate, graveyard/reanimation, spells, artifacts, lifegain), choose a real suggested commander, source mode and USD budget. This is explicitly a rules-based builder, not model AI or general natural-language understanding. No paid/model calls. Existing model-backed upgrades remain separate and unchanged in purpose, requiring a configured credential/account; in-deck heuristic recommendations remain available to guests.

Source modes: collection only, buy every copy, or use collection then missing copies. Budget means either total deck market value INCLUDING owned cards or new purchases only. Owned quantities come from active binders, across printings; decks/wishlists do not count and ownership is not decremented. All unique owned printings are reverified sequentially in25-item progress chunks, with cancellation and no partial feasibility result; the former200-printing cap has been removed. The pool is finite and greedy, so an unsuccessful draft is not proof no possible deck exists.

Targets one commander +63 noncommander spells +36 lands, prioritizing an inexpensive basic base and role/strategy candidates. Exact100 count, verified Commander legality, color identity, singleton/explicit copy exceptions, available owned quantities and budget are required before the Save reviewed complete deck button enables. Unsupported special construction conditions prevent a complete claim. Unknown prices cannot become free purchases/market value; unpriced OWNED cards can fit a purchase-only budget while total market value is explicitly unavailable. Complete lists are reviewable with strategy/role explanation, estimated total/new purchases and missing copies. Scryfall USD snapshots may be cached up to24h; retrieval time is displayed. Prices exclude taxes/shipping and are not offers. No purchases occur. One-commander construction, finite provider pool and six supported themes are intentional current boundaries; partner pairs/general model interpretation are not implemented.
